# NetFinder Contribution Guidelines

## 1. Branch Rules
- Never push directly to main or development.
- Create a feature branch for every task.
- Use the naming convention:
  feature/team-task-name

## 2. Pull Requests
- All contributions must go through Pull Requests.
- Pull Requests must target development.
- Every Pull Request requires approval from someone on another team.
- Project Managers oversee merges.

## 3. Commit Messages
Use clear commit messages.

Examples:
- feat: add speed test page
- fix: correct GPS location bug
- docs: update project documentation
- test: add API test cases

## 4. Code Quality
- Test your code before pushing.
- Follow the NetFinder project blueprint.
- Never submit code you cannot explain.

## 5. Security
- Never commit passwords or secret API keys.
- Use .env.example for environment variable documentation.
- Keep actual .env files private.

## 6. Teamwork
- Communicate progress during daily standups.
- Update GitHub issue statuses.
- Report blockers early.
